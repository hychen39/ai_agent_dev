# Python 泛型（Generics）簡介

## 什麼是泛型？

泛型（Generic）是一種**將資料型別參數化（parameterized
types）**的設計方式。

它的核心精神可以用一句話表示：

> **在設計階段，將演算法與資料型別分離；在使用階段，再決定實際的資料型別。**

------------------------------------------------------------------------

## 為什麼需要泛型？

假設要設計一個 Stack。

若沒有泛型，就可能需要分別撰寫：

-   `IntStack`
-   `StringStack`
-   `UserStack`
-   `OrderStack`

雖然資料型別不同，但 **push**、**pop** 等演算法完全相同。

因此，我們希望：

-   演算法只寫一次
-   資料型別交由使用者決定

這就是泛型的目的。

------------------------------------------------------------------------

## 泛型的設計流程

### Step 1：設計（Design）

設計類別或函式時，只關心演算法，不指定資料型別。

``` python
class Stack[T]:

    def push(self, item: T):
        ...

    def pop(self) -> T:
        ...
```

此時：

-   已決定演算法
-   尚未決定 `T` 是什麼型別

------------------------------------------------------------------------

### Step 2：指定型別（Instantiation）

真正使用時，再指定型別。

``` python
Stack[int]
```

或

``` python
Stack[str]
```

或

``` python
Stack[User]
```

此時：

    T → int

或

    T → User

------------------------------------------------------------------------

### Step 3：使用（Use）

``` python
stack = Stack[int]()

stack.push(10)
```

由於 `T` 已經被指定為 `int`，因此：

``` python
stack.push("Hello")   # 型別檢查工具會提示錯誤
```

------------------------------------------------------------------------

## 泛型可以想成一個模板

設計時：

    Stack<_____>

作者保留型別的位置。

使用者再填入：

    Stack<int>

    Stack<User>

    Stack<Order>

因此：

-   演算法固定
-   型別可替換

------------------------------------------------------------------------

## LangChain 範例

例如：

``` python
ToolRuntime[ContextT, StateT]
```

LangChain 作者在設計 `ToolRuntime` 時，不知道每個 Agent 的 State
長什麼樣子，因此使用泛型：

``` python
class ToolRuntime[ContextT, StateT]:
    ...
```

真正使用時：

``` python
runtime: ToolRuntime[None, OrderState]
```

此時：

    ContextT → None
    StateT   → OrderState

IDE 就能知道 `runtime.state` 具有 `OrderState` 的所有欄位。

------------------------------------------------------------------------

## 泛型的優點

-   **提高程式重用性**：同一份程式可支援多種資料型別。
-   **降低重複程式碼**：避免為每種型別撰寫相同演算法。
-   **提升型別安全**：型別檢查工具可提前發現錯誤。
-   **改善 IDE 體驗**：提供更精確的自動完成與型別推論。

------------------------------------------------------------------------

## 重點整理

> **泛型（Generic）是一種延後型別決策（Deferred Type
> Binding）的設計方法。**

設計者只需專注於演算法：

    演算法
        │
        ▼
    Generic<T>
        │
        ▼
    使用者指定型別
        │
        ▼
    Stack<int>
    Stack<User>
    Stack<Order>

因此可以在**設計階段將演算法與資料型別分離**，並在**使用階段再決定實際型別**，兼顧程式重用性與型別安全。
